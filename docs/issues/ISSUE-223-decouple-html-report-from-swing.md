# ISSUE-223: Decouple parser HTML report generation from Swing/viewer assumptions

- Status: planned
- Roadmap: [iped-parsers-ROADMAP.md](../roadmaps/iped-parsers-ROADMAP.md)
- Roadmap section: Phase 3 — Architecture
- Owner: unassigned
- Created: 2026-06-21
- Updated: 2026-06-21

## Summary

Parser-generated HTML reports currently assume the legacy Swing viewer environment;
this needs to be decoupled so report output renders identically in the browser UI,
as part of the 5.0 workstream 1 effort.

## Problem

Report HTML generated by parsers (e.g. chat/UFED report templates) is tied to
Swing/viewer-specific assumptions, preventing identical rendering in the new
browser-based UI.

## Acceptance criteria

- [ ] Identify all Swing/viewer-specific assumptions baked into parser HTML report
      generation.
- [ ] Decouple report generation so output renders identically in the browser UI.
