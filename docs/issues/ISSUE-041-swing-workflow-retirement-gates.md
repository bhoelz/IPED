# ISSUE-041: Per-workflow retirement gates for Swing workflows

- Status: planned
- Roadmap: [iped-app-ROADMAP.md](../roadmaps/iped-app-ROADMAP.md)
- Roadmap section: Phase 4 — Decommission decisions
- Owner: unassigned
- Created: 2026-06-21
- Updated: 2026-06-21

## Summary

Define and enforce retirement gates so that each Swing workflow is removed only after its browser UI equivalent has passed parity sign-off on real cases.

## Problem

Without explicit per-workflow retirement gates, there is a risk of removing Swing functionality before the browser UI replacement is genuinely ready for real-world use.

## Acceptance criteria

- [ ] Retirement gate process defined: a Swing workflow is removed only after the browser equivalent passes parity sign-off on real cases.
- [ ] Gate applied consistently as each Swing workflow is considered for removal.
