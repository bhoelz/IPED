## Summary

Fechar as lacunas entre o inventário da UI Swing, os contratos já existentes (OpenAPI, schema de eventos) e um backlog executável para a web UI, antes de iniciar a implementação do skeleton.

## Problem

Sem uma matriz de rastreabilidade Swing -> capability web e sem decisões de arquitetura frontend firmadas, o time corre risco de implementar a web UI sem cobertura clara das capacidades críticas do Swing.

## Acceptance criteria

- [x] Matriz de rastreabilidade Swing -> capability web criada.
- [x] Mapa de estado da aplicação web definido.
- [x] Decisões de arquitetura frontend e convenções de pastas/estado/eventos registradas.
- [x] Priorização oficial do MVP definida.
- [x] Toda capability do MVP vinculada a endpoint/evento existente ou pendência explícita.
